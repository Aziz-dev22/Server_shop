# 🤖 Hetzner Shop Bot

ربات تلگرامی فروش و مدیریت سرور مجازی (VPS) روی Hetzner Cloud + پنل مدیریت تحت وب — کاملاً آماده و بدون نیاز به دانش برنامه‌نویسی.

فقط ۶ فایل دارد:

| فایل | کاربرد |
|---|---|
| `bot.py` | کل منطق ربات تلگرام |
| `panel.py` | پنل مدیریت تحت وب (از همان دیتابیس و منطق `bot.py` استفاده می‌کند) |
| `requirements.txt` | لیست کتابخانه‌های موردنیاز |
| `.env.example` | نمونه فایل تنظیمات |
| `install.sh` | نصب / آپدیت / بکاپ / حذف با یک دستور (هر دو سرویس ربات و پنل را مدیریت می‌کند) |
| `README.md` | همین راهنما |

دیتابیس از نوع **SQLite** است (یک فایل، بدون نیاز به نصب دیتابیس جداگانه).

## ✅ چه امکاناتی دارد؟

**برای کاربر:**
- ثبت‌نام خودکار با اولین `/start`
- خرید سرور: انتخاب دیتاسنتر → پلن → سیستم‌عامل → پرداخت از کیف پول → تحویل خودکار IP و پسورد
- **همه قیمت‌ها به دلار ($) و به‌صورت زنده از قیمت واقعی اکانت Hetzner محاسبه می‌شوند** (به‌علاوه درصد سودی که ادمین تعیین کرده)
- مشاهده و مدیریت سرورها (روشن / خاموش / ریبوت / تغییر پسورد / **نصب مجدد سیستم‌عامل (Rebuild)** / حذف)
- مشاهده تاریخچه سفارش‌ها
- شارژ کیف پول به دو روش:
  - 💠 **پرداخت خودکار با ارز دیجیتال** (از طریق OxaPay، بدون نیاز به تایید دستی)
  - 🏦 **واریز دستی** به کارت یا آدرس ولتی که ادمین مشخص کرده (با تایید دستی ادمین)
- پروفایل کاربری
- پشتیبانی (ارسال پیام مستقیم به ادمین)

**برای ادمین (با دستور `/admin` در تلگرام یا از پنل تحت وب):**
- مشاهده کاربران، سفارش‌ها و آمار کلی (تعداد کاربران، سرورها، درآمد)
- **مدیریت چند API Key هتزنر همزمان** — افزودن، مشاهده، فعال‌سازی و حذف هرکدام
- تعریف پلن‌های فروش فقط با انتخاب نوع سرور واقعی Hetzner و تعیین **درصد سود** (قیمت نهایی خودش زنده محاسبه می‌شود) — هر پلن می‌تواند مخصوص یک لوکیشن خاص یا همه لوکیشن‌ها باشد
- **فعال/غیرفعال کردن هر دیتاسنتر Hetzner به‌صورت جداگانه** برای فروش
- پلن‌هایی که هم‌اکنون در آن دیتاسنتر موجودی سخت‌افزاری ندارند به‌صورت خودکار از دید کاربر پنهان می‌شوند
- تنظیم درگاه پرداخت ارز دیجیتال (OxaPay API Key)
- تنظیم آدرس واریز دستی (شماره کارت یا آدرس ولت)
- **دسترسی کامل به همه‌ی سرورهای همه‌ی کاربران** با دکمه‌های روشن/خاموش/ریبوت/پسورد/Rebuild/حذف — حتی سرورهایی که مستقیماً در پنل Hetzner (نه از طریق ربات) ساخته شده‌اند، با «همگام‌سازی» به‌صورت خودکار پیدا و قابل‌مدیریت می‌شوند
- **مدیریت کامل هر کاربر با یک کلیک**: افزایش/کاهش موجودی کیف پول، دیدن و مدیریت سرویس‌هایش، مسدود/رفع مسدودیت
- **ساخت سرور رایگان برای خودش** (بدون کسر از کیف پول) از هر نوع و در هر دیتاسنتری
- تایید یا رد درخواست‌های شارژ دستی
- ارسال پیام همگانی به تمام کاربران
- در هر صفحه از ربات دکمه «🔙 بازگشت» وجود دارد، بدون نیاز به `/start` مجدد

**🌐 پنل مدیریت تحت وب (`panel.py`):**
تمام امکانات بالای بخش ادمین از یک آدرس اینترنتی هم در دسترس است — مناسب کسانی که ترجیح می‌دهند از مرورگر مدیریت کنند. با نام کاربری/رمز عبوری که هنگام نصب تعیین می‌کنید وارد می‌شوید و دقیقاً همان دیتابیس ربات را می‌بینید و مدیریت می‌کنید (هیچ تنظیم تکراری لازم نیست).

## 🚀 نصب / آپدیت / بکاپ / حذف (با یک دستور)

روی سرور اوبونتو (Ubuntu 22.04 یا 24.04) این یک خط را اجرا کنید:

```bash
sudo bash <(curl -fsSL https://raw.githubusercontent.com/Aziz-dev22/server_shop/main/install.sh)
```

یک منو با ۴ گزینه نمایش داده می‌شود:

```
1) نصب                 → نصب کامل ربات از صفر
2) آپدیت                → دریافت آخرین نسخه کد از گیت‌هاب (تنظیمات و دیتابیس حفظ می‌شود)
3) بکاپ کامل             → گرفتن یک فایل فشرده از کل ربات (تنظیمات + دیتابیس)
4) حذف کامل             → توقف و پاک‌سازی کامل ربات از روی سرور (با تاییدیه و امکان بکاپ قبل از حذف)
```

عدد مربوطه را وارد کرده و Enter بزنید.

هنگام **نصب**، این موارد پرسیده می‌شود:
1. **توکن ربات تلگرام** — از [@BotFather](https://t.me/BotFather) با دستور `/newbot`
2. **شناسه عددی تلگرام ادمین** — از [@userinfobot](https://t.me/userinfobot)
3. **نام کاربری و رمز عبور دلخواه برای ورود به پنل تحت وب**

بقیه تنظیمات (اتصال Hetzner، درگاه ارزی، آدرس واریز، پلن‌ها، لوکیشن‌ها) از **داخل خود ربات با `/admin`** یا از **پنل تحت وب** انجام می‌شود.

## ⚙️ راه‌اندازی اولیه بعد از نصب (داخل تلگرام)

1. به ربات خودتان پیام `/start` بدهید.
2. دستور `/admin` را بزنید تا پنل مدیریت باز شود.
3. روی **«🔑 مدیریت API های Hetzner»** بزنید → **«➕ افزودن API جدید»** → یک نام دلخواه و سپس API Token پروژه Hetzner Cloud خود را وارد کنید.
   - توکن را از پنل Hetzner: `Project > Security > API Tokens` با دسترسی **Read & Write** بسازید.
   - می‌توانید چند اکانت/پروژه هتزنر اضافه کنید و هر زمان بین آن‌ها جابه‌جا شوید.
4. روی **«🧩 مدیریت پلن‌ها»** → **«➕ افزودن پلن جدید»** بزنید، یکی از سرورهای واقعی Hetzner را انتخاب کنید، یک اسم دلخواه بگذارید و **درصد سود** را وارد کنید (مثلاً 20 برای ۲۰٪ سود روی قیمت پایه هتزنر). دیگر نیازی به وارد کردن قیمت دستی نیست.
5. اگر می‌خواهید پرداخت خودکار ارز دیجیتال فعال باشد: روی **«💠 درگاه ارز دیجیتال (OxaPay)»** بزنید و Merchant API Key حساب OxaPay خودتان را وارد کنید (بدون نیاز به دامنه یا وب‌هوک، ربات خودش وضعیت پرداخت را چک می‌کند).
6. روی **«🏦 آدرس واریز دستی»** بزنید و شماره کارت یا آدرس ولت ارز دیجیتالی که برای واریز دستی کاربران استفاده می‌شود را وارد کنید.
7. از همین حالا کاربران می‌توانند از منوی **«🛒 خرید سرور»** خرید کنند.

## 🔧 دستورات مدیریت سرویس

```bash
systemctl status hetzner-shop-bot       # وضعیت ربات
journalctl -u hetzner-shop-bot -f       # مشاهده لاگ زنده ربات
systemctl restart hetzner-shop-bot      # ری‌استارت ربات

systemctl status hetzner-shop-panel     # وضعیت پنل تحت وب
journalctl -u hetzner-shop-panel -f     # مشاهده لاگ زنده پنل
systemctl restart hetzner-shop-panel    # ری‌استارت پنل
```

پنل تحت وب پیش‌فرض روی پورت `8088` بالا می‌آید: `http://IP-SERVER:8088`
مطمئن شوید این پورت در فایروال سرور باز است، مثلاً:
```bash
ufw allow 8088
```
برای امنیت بیشتر توصیه می‌شود پنل را پشت یک دامنه و HTTPS (با nginx + certbot) قرار دهید.

## 💡 نکات مهم

- قیمت‌های هتزنر معمولاً به **یورو** برگردانده می‌شوند؛ ربات به‌صورت خودکار با نرخ لحظه‌ای یورو/دلار (که هر ۶ ساعت بروزرسانی می‌شود) آن را به دلار تبدیل کرده و سپس درصد سود ادمین را روی آن اعمال می‌کند.
- درگاه OxaPay نیازی به دامنه یا وب‌هوک عمومی ندارد؛ ربات هر ۴۵ ثانیه وضعیت فاکتورهای پرداخت‌نشده را از OxaPay استعلام می‌گیرد و بعد از تایید، خودش کیف پول را شارژ می‌کند.
- اگر هنوز درگاه ارز دیجیتال را تنظیم نکرده باشید، فقط گزینه «واریز دستی» به کاربران نمایش داده می‌شود.
- فایل دیتابیس `shop.db` داخل پوشه `/opt/hetzner-shop-bot` ساخته می‌شود؛ گزینه «بکاپ کامل» در نصب‌کننده این فایل را همراه تنظیمات، به‌صورت خودکار در `/root/hetzner-shop-bot-backups` ذخیره می‌کند.
- برای بروزرسانی ربات در آینده، فقط دستور نصب یک‌خطی را دوباره اجرا کرده و گزینه «۲) آپدیت» را انتخاب کنید.


### بکاپ خودکار و عضویت اجباری در پنل تحت وب

از منوی «بکاپ خودکار و عضویت اجباری» می‌توانید کانال مقصد بکاپ، فاصله زمانی (مانند `30m` یا `2h`)، فعال/غیرفعال بودن بکاپ و کانال عضویت اجباری را تنظیم کنید. پنل وضعیت هر دو قابلیت، آخرین بکاپ و زمان برنامه‌ریزی‌شده بکاپ بعدی را نشان می‌دهد. دکمه «ارسال بکاپ آزمایشی» فایل ZIP پروژه را به کانال انتخاب‌شده می‌فرستد و در صورت خطا، جزئیات خطا را نمایش می‌دهد. فایل `.env` برای محافظت از اطلاعات محرمانه وارد بکاپ نمی‌شود.

برای ارسال بکاپ، ربات را در کانال مقصد ادمین کنید و اجازه ارسال فایل بدهید. برای عضویت اجباری نیز ربات باید بتواند وضعیت عضویت کاربران را از کانال بررسی کند.

## تغییرات موجودی و وضعیت اکانت‌ها

- در خرید سرور، موجودی هر پلن Hetzner از `server_types[].locations[].available` استعلام می‌شود. پلن ناموجود با برچسب «ناموجود» نمایش داده می‌شود و انتخاب آن مسدود است.
- در فهرست پلن‌های هر لوکیشن ربات، دکمه «همگام‌سازی موجودی» برای استعلام دوباره اضافه شده است.
- پنل وب بخش «لیمیت، CPU و Usage اکانت‌ها» دارد و سرورها، هسته‌های CPU و RAM مصرف‌شده و هزینه ماهانه تخمینی را برای هر API نشان می‌دهد.
- Hetzner Cloud API لزوماً حد مجاز پروژه یا بدهی/صورتحساب واقعی را برنمی‌گرداند. اگر مقدار لیمیت خودکار در دسترس نباشد، می‌توان حد سرور و CPU را از کنسول Hetzner در همان صفحه دستی ثبت کرد. هزینه نمایش‌داده‌شده تخمینی است، نه بدهی قطعی.

## تغییرات تکمیلی (اکانت‌های API و پشتیبانی)

- چند API از یک نوع می‌توانند هم‌زمان فعال باشند؛ فعال/غیرفعال بودن API فقط روی استفاده برای فروش جدید اثر دارد.
- اولویت فروش هر نوع سرویس‌دهنده جداگانه قابل تعیین است. خریدهای جدید از API اولویت‌دار فعال استفاده می‌کنند.
- سرورهای جدید شناسه API مالک خود را ذخیره می‌کنند؛ مدیریت سرور (روشن/خاموش، ریبوت، تغییر پسورد، حذف، بازسازی و تغییر IP) از همان API مالک انجام می‌شود، حتی اگر برای فروش غیرفعال شده باشد. برای رکوردهای قدیمی، سیستم تلاش می‌کند API مالک را با شناسه سرور پیدا و ذخیره کند.
- تیکت‌ها شناسه دارند و ادمین می‌تواند از منوی «تیکت‌ها و تنظیمات پشتیبانی» در ربات به همان کاربر پاسخ دهد.
- روشن/خاموش کردن سیستم تیکت و تنظیم آیدی/لینک و متن نمایشی پشتیبانی از منوی ادمین ربات و صفحه «تیکت و پشتیبانی» پنل وب ممکن است.


## تغییرات نسخه ویرایش‌شده

- نمایش زمان سپری‌شده، مصرف ترافیک ورودی/خروجی و حجم باقی‌مانده بر اساس اطلاعات زنده API هتزنر؛ در ربات و پنل، همراه با همگام‌سازی.
- در آستانه ۱۹.۵ ترابایت، سرور برای هشدار خاموش می‌شود؛ در تکمیل حجم مجاز، درخواست حذف/تمدید برای ادمین ارسال می‌شود و حذف خودکار انجام نمی‌شود.
- پایان مهلت سرویس: سرور خاموش می‌شود و پس از مهلت ارفاقی، درخواست تأیید حذف برای ادمین ارسال می‌شود؛ ادمین می‌تواند حذف را تأیید یا تمدید را آغاز کند.
- حذف سرور از منوی کاربر نیز ابتدا سرور را خاموش و درخواست تأیید ادمین ثبت می‌کند.
- APIهای فعال هتزنر برای بررسی موجودی پلن‌ها بررسی می‌شوند؛ API اولویت فروش اول استفاده می‌شود و در صورت ناموجود بودن، حساب‌های دیگر امتحان می‌شوند.
- هنگام تغییر IP، IP قبلی آزاد (unassign) می‌شود اما تا ۳۰ دقیقه نگه داشته می‌شود؛ پاک‌سازی آن توسط وظیفه دوره‌ای انجام می‌شود.


## قابلیت‌های افزوده‌شده در نسخه توسعه‌یافته

- منطقه زمانی نمایش تاریخ‌ها و انقضا: `Asia/Tehran`؛ زمان‌های دیتابیس برای سازگاری به شکل UTC نگهداری می‌شوند.
- سقف نهایی ترافیک در کد روی ۲۰ ترابایت محدود شده است؛ هشدار/خاموشی محافظتی فعلی از ۱۹٫۵ ترابایت شروع می‌شود.
- سرورهای ساخته‌شده خارج از ربات در همگام‌سازی با مهلت ۳۰ روزه و مبلغ تمدید صفر ثبت می‌شوند تا امکان تمدید از طریق ادمین وجود داشته باشد. برای مالکیت دقیق‌تر، پس از همگام‌سازی می‌توان مالک را از پنل تعیین کرد.
- سرورهای متعلق به شناسه‌های `ADMIN_IDS` و سرورهای ساخته‌شده از مسیر مستقیم ادمین محافظت می‌شوند و وارد چرخه خاموشی/حذف خودکار نمی‌شوند.
- فروشگاه عمومی در مسیر `/shop` و مدیریت محصولات و سفارش‌ها در مسیرهای `/products` و `/product-orders` پنل قرار دارد. مدیریت سریع سفارش‌ها نیز با دستور `/shoporders` برای ادمین در ربات قابل مشاهده است؛ `/shop` فهرست محصولات را نشان می‌دهد.
- پرداخت زرین‌پال از مسیر تنظیمات `/settings/zarinpal` فعال می‌شود. برای پرداخت واقعی، دامنه HTTPS را در `PUBLIC_BASE_URL` قرار دهید و مرچنت‌کد واقعی را ذخیره کنید. حالت Sandbox برای آزمایش است.
- اتصال اینماد وابسته به ثبت دامنه، دریافت نماد از اینماد و درج کد/لینک تأیید صادرشده برای همان دامنه است؛ پس از تایید دامنه، کد رسمی نمایش اینماد را در `ENAMAD_WIDGET_HTML` قرار دهید؛ صدور خود نماد از داخل برنامه انجام نمی‌شود.

**تحویل خودکار محصولات دیجیتال آماده:** هنگام ساخت یا ویرایش محصول، روش «خودکار از موجودی اقلام آماده» را انتخاب کنید؛ سپس از دکمه «مدیریت اکانت‌ها» برای همان محصول، هر اکانت/کد/لینک را در یک خط به موجودی اضافه کنید. برای اکانت می‌توانید از قالب `username|password|notes` استفاده کنید و برای کد یا لینک، مقدار را در یک خط وارد کنید. پس از تأیید پرداخت زرین‌پال، اقلام به‌صورت اتمیک به سفارش تخصیص داده می‌شوند و لینک امن تحویل به خریدار نمایش داده می‌شود؛ موجودی خودکار کاهش می‌یابد و callback تکراری سفارش را دوباره تحویل نمی‌دهد. لینک تحویل محرمانه است و هرکس آن را داشته باشد می‌تواند اطلاعات را ببیند؛ آن را فقط از طریق HTTPS و با `PUBLIC_BASE_URL` صحیح منتشر کنید. اطلاعات موجودی در دیتابیس ذخیره می‌شوند؛ دسترسی فایل دیتابیس و بکاپ‌ها را محدود و رمزگذاری کنید. محصولات با روش «دستی» همچنان نیازمند تحویل دستی هستند. تصاویر محصولات از طریق نشانی URL ثبت می‌شوند؛ ارسال مستقیم فایل از پنل در این نسخه وجود ندارد، اما لینک دانلود را می‌توان به‌عنوان قلم دیجیتال تحویل داد.

## ورود مشتری، خرید یکپارچه و پرداخت ترکیبی (نسخه تکمیلی)

### ورود / ثبت‌نام مشتری

- مسیر ورود مشتری: `/customer/login` (از ورود مدیر پنل `/login` جداست).
- ورود تلگرام با Telegram Login Widget انجام می‌شود. در BotFather باید دامنه HTTPS سایت را برای همان ربات ثبت کنید (`/setdomain`). مقدار `TELEGRAM_LOGIN_BOT` در `.env` باید نام کاربری ربات بدون `@` باشد.
- ورود ایمیلی با کد یک‌بارمصرف انجام می‌شود. ارسال ایمیل به SMTP نیاز دارد؛ متغیرهای `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` را تنظیم کنید. پورت پیش‌فرض 587 و TLS فعال است.
- کاربری که ابتدا با ایمیل وارد شده می‌تواند از حساب کاربری روی «اتصال تلگرام» بزند و حساب تلگرام را به همان حساب وصل کند. هنگام اتصال، موجودی کیف پول و سفارش‌ها به حساب تلگرام منتقل می‌شوند.
- نشست مشتری و نشست مدیر جدا هستند. نشست‌ها در حافظه برنامه نگهداری می‌شوند و پس از راه‌اندازی مجدد سرویس، کاربر باید دوباره وارد شود.

### خرید محصولات دیجیتال

- سایت: `/shop`؛ خرید مستلزم ورود مشتری است.
- ربات: دستور `/shop` یا دکمه «فروشگاه اکانت». خرید کامل با کیف پول داخل ربات انجام می‌شود؛ اگر موجودی کافی نباشد یا مشتری پرداخت ترکیبی/درگاه بخواهد، لینک یک‌بارمصرف ورود به سایت با همان محصول ارائه می‌شود.
- روش‌های پرداخت فروشگاه: کیف پول کامل، زرین‌پال، OxaPay، NOWPayments و ترکیب کیف پول با هرکدام از درگاه‌های فعال.
- اقلام خودکار فقط پس از تأیید پرداخت از موجودی خارج می‌شوند. سفارش و تراکنش کیف پول شناسه یکتا دارند تا برداشت/تحویل تکراری رخ ندهد.
- سفارش‌ها و اطلاعات تحویل در «حساب من» و نیز با دکمه سفارش‌های دیجیتال در ربات قابل مشاهده‌اند.

### خرید سرور از وب‌سایت

- مسیر: `/servers/buy`؛ مشتری پس از ورود، سرویس‌دهنده، دیتاسنتر، پلن و سیستم‌عامل را انتخاب می‌کند.
- خرید سرور از وب از کیف پول، پرداخت مستقیم با درگاه یا پرداخت ترکیبی کیف پول و مابه‌التفاوت پشتیبانی می‌کند.
- اگر خرید سرور از ربات با موجودی ناکافی متوقف شود، ربات لینک امن و یک‌بارمصرفی به همین مرحله وب با پلن انتخاب‌شده می‌دهد.
- سفارش‌های وب سرور در پنل مدیریت از مسیر «سفارش‌های سرور وب» قابل پیگیری هستند.

### نرخ تبدیل کیف پول

قیمت محصولات به تومان و کیف پول به دلار است. نرخ تبدیل را از پنل مدیریت، «نرخ تبدیل کیف پول» تنظیم کنید. مقدار پیش‌فرض دیتابیس 100000 تومان برای هر دلار است؛ این مقدار صرفاً مقدار اولیه است و مدیر باید نرخ واقعی فروش خود را تعیین کند. تغییر نرخ فقط روی سفارش‌های جدید اعمال می‌شود؛ نرخ هر سفارش نیز در همان سفارش ذخیره می‌شود.

### الزامات پیش از فعال‌سازی

1. `PUBLIC_BASE_URL` را با آدرس عمومی HTTPS سایت تنظیم کنید.
2. `COOKIE_SECURE=1` را در سایت HTTPS حفظ کنید.
3. `TELEGRAM_LOGIN_BOT` را تنظیم و دامنه سایت را در BotFather برای همان ربات ثبت کنید.
4. SMTP را برای ورود ایمیلی تست کنید.
5. مرچنت زرین‌پال و کلیدهای OxaPay/NOWPayments را در پنل تنظیم کنید. گزینه‌های پرداخت فقط زمانی نمایش داده می‌شوند که درگاه مربوطه پیکربندی شده باشد.
6. سرویس ربات باید فعال بماند؛ بررسی دوره‌ای پرداخت‌های OxaPay و NOWPayments توسط poller ربات انجام می‌شود.
7. پیش از فروش واقعی، پرداخت آزمایشی کم‌مبلغ و یک خرید با کیف پول، یک خرید ترکیبی، یک خرید مستقیم درگاه و یک خرید سرور آزمایشی انجام دهید.

> نکته عملیاتی: اگر پرداخت خارجی موفق شود ولی سرویس‌دهنده هنگام ساخت سرور خطا بدهد، سهم کیف پول به‌صورت خودکار برگشت داده می‌شود و سفارش با وضعیت `creation_failed` در پنل باقی می‌ماند؛ مبلغ خارجی باید از طریق پشتیبانی درگاه بررسی/بازپرداخت شود. پرداخت واقعی درگاه‌ها و اتصال SMTP در محیط توسعه این پروژه قابل آزمایش نبوده و باید روی دامنه و کلیدهای واقعی شما تست شود.


## امکانات تکمیلی مدیریت خرید و کیف پول

- در پنل مدیریت، مسیر `/admin-wallet-purchase` برای خرید اکانت از کیف پول مشتری اضافه شده است.
- مسیر `/admin-server-purchase` برای ساخت سرور به نام مشتری و کسر مبلغ از کیف پول او اضافه شده است. شناسه مشتری می‌تواند شناسه تلگرام یا شناسه داخلی منفی حساب ایمیلی باشد.
- خرید مدیریتی و تمدید از پنل می‌تواند موجودی مشتری را منفی کند؛ این مجوز به خرید مستقیم مشتری منتقل نمی‌شود.
- عملیات مدیریتی در `admin_wallet_actions` و دفتر تراکنش‌های کیف پول ثبت می‌شود.
- تمدید سرور از پنل مدیریت با قفل تراکنشی انجام می‌شود و اگر روشن‌کردن خودکار سرور شکست بخورد، خطا در پیام اطلاع‌رسانی درج می‌شود.
- سفارش‌های اکانت: تحویل دستی فقط برای سفارش پرداخت‌شده مجاز است. بازپرداخت کیف پول فقط یک‌بار ثبت می‌شود؛ برای پرداخت‌های درگاهی، سهم کیف پول بازگردانده و سفارش برای بازپرداخت دستی در درگاه علامت‌گذاری می‌شود.
- محصولات تمام‌شده از فهرست فروش و مدیریت فعال پنهان می‌شوند، اما رکورد محصول برای حفظ تاریخچه سفارش باقی می‌ماند. در بازپرداخت مجاز سفارش دستی، موجودی محصول دوباره فعال می‌شود.


## جداسازی فروشگاه عمومی و پنل مدیریت

- فروشگاه عمومی در برنامه مستقل `website.py` اجرا می‌شود و Nginx درخواست‌های پورت 80 را به آن روی `127.0.0.1:8080` هدایت می‌کند. مشتری فقط IP یا دامنه را بدون پورت وارد می‌کند.
- پنل مدیریت در برنامه مستقل `panel.py` اجرا می‌شود و مستقیماً روی `0.0.0.0:8088` در دسترس است: `http://SERVER-IP:8088/`.
- ربات تلگرام همچنان در `bot.py` و سرویس systemd مستقل خود اجرا می‌شود.
- مسیرهای مشتری (ورود، حساب کاربری، فروشگاه اکانت، پرداخت و خرید سرور) فقط در برنامه `website.py` ثبت شده‌اند؛ مسیرهای مدیریت فقط در `panel.py` ثبت می‌شوند. توابع و دیتابیس مشترک از ماژول موجود استفاده می‌کنند تا منطق سفارش و کیف پول دو نسخه نشود.
- سرویس‌های systemd: `hetzner-shop-bot`, `hetzner-shop-panel`, `hetzner-shop-website`.
- آپدیت با گزینه ۲ نصب‌کننده، هر سه سرویس را بازسازی و راه‌اندازی می‌کند؛ فایل‌های `.env` و `shop.db` در آپدیت حذف نمی‌شوند.

> نکته امنیتی: دسترسی مستقیم پنل مدیریت روی پورت 8088 با HTTP رمزگذاری نمی‌شود. برای استفاده واقعی از اینترنت عمومی، آن را با فایروال محدود به IP ادمین یا پشت HTTPS قرار دهید. ورود تلگرام و callback درگاه‌ها نیز برای استفاده واقعی به دامنه HTTPS و تنظیم صحیح `PUBLIC_BASE_URL` نیاز دارند.
